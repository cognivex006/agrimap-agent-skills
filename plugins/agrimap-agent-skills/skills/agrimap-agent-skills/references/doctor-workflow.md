# AGM installation maintenance

These are Agent-chat actions, not a new shell executable. Resolve exactly one action: status (no arguments), version, check or update. Accept `--host codex|claude|antigravity`, with `agy` normalized to antigravity, and `--to <version>` only for update. A legacy `gemini` host stays distinct: report its installation read-only and recommend Antigravity migration; do not silently select or uninstall another host. Quoted examples/help never authorize installation.

## Read-only discovery and reporting

Use the actual host/session and loaded skill location as evidence. With --host, inspect that host's installed registry and package path; never report this session's package as the other host's installed version. Discover executables with Get-Command/command -v and read their version and plugin help. A desktop host can have an active plugin without its CLI on PATH: distinguish a working installation from unavailable terminal management. Resolve an ambiguous host only for dependent work, not by inferring it from the model.

Read version from the installed package manifest: Codex/Claude `.codex-plugin/plugin.json` or `.claude-plugin/plugin.json`; Antigravity's staged root `package.json` (its plugin.json schema has no version field). Cross-check the bundled `assets/bootstrap/manifest.json` and `assets/tool-versions.json` skillVersion. Report loaded-session version, installed version, source/path and host version separately. Missing/disagreeing manifests mean unknown/inconsistent, never current. Do not dump user configuration, tokens or credentials.

For version, query the registered AGM source read-only. For the official source use https://github.com/cognivex006/agrimap-agent-skills, resolve its actual default branch/ref, and inspect package.json plus marketplace metadata at the same commit. Label an installable branch snapshot separately from a tagged release; compare semantic versions, not strings. Check a requested tag's manifest before recommending it. Network/auth failures leave available version unknown while preserving installed evidence. Never refresh a marketplace or write a clone during status/version/check. Include source/ref and observation date; local source version alone does not prove a newer package was published.

Status gives a short local overview; check inspects applicable workflows. Use a table with capability, observed/required value, status, scope and repair. Status values: ready, recommended, missing-required, unknown. List an absent optional workflow dependency as missing-required *for that workflow*, not as a global failure. Only report passed checks actually performed.

| Capability | Evidence and applicability | Repair advice, never executed by check |
| --- | --- | --- |
| AGM runtime | Node.js >=20 and readable bundled entrypoints/scripts | Install a supported Node runtime or repair the package |
| Installation management | Selected host plugin help, registry/path and source; Git for Git-based updates | Use that host's supported manager; fix PATH only when proven |
| SQL formatting | `sqlfluff --version` versus exact `assets/tool-versions.json` pin; Python/pip availability when repair is needed | Run bundled install-sqlfluff.mjs only in separately authorized SQL formatting/tool repair |
| Managed SQL context | Availability of sql-context-pack and its connected read-only profile | Connect the missing service/profile; never expose credentials or probe database writes |
| Product release | Git, .NET SDK/runtime, exact global package AgriMap.ProjectDevKit.NetCore.Release and its executable | Follow release-tools.md during an authorized product release; not required for doctor/package updates |
| Stray state roots | `strayStateRoots` from `agm-workspace.mjs context --cwd <session cwd>`: `.agrimap-agent/` outside any Git root; status recommended | Move wanted files into the target repository yourself; doctor never deletes or moves them |
| Workflow policy | `policy show` in the target repository: exists, valid, confirmed | Answer the first-run policy card; fix listed validation details |
| Guards | `governance.guards` in the target config; host: Claude `PreToolUse` (Bash|PowerShell) and `Stop` installed; Codex, Gemini/Antigravity `not-supported-on-host` (deliver/integrate scripts still enforce) | Set `governance.guards: false` only to switch the project off |
| Skill gate | `governance.skillGate` (and `guards`) in the target config; host: Claude `PreToolUse` Edit/Write skill-gate installed; Codex, Gemini/Antigravity `not-supported-on-host` (AGENTS §0 and the prompt hook still route) | Set `governance.skillGate: false` only to switch the project off |
| Workspace routing | A non-Git folder holding several AgriMap repositories has an AGENTS.md carrying the workspace routing marker | Recommend `skill-routing.mjs workspace --cwd <folder>` (plan); the owner runs `--apply` |
| Project bootstrap | When a product target is in scope, compare its AGENTS marker/receipt with this bundle | Recommend agm-release bootstrap upgrade; do not apply it from doctor |

Detect missing tools using read-only version/help/list commands with bounded timeouts. Do not run install-sqlfluff.mjs, audit a product through a mutating tool, execute tests, install dependencies or repair configuration during checks. A dependency's presence does not prove end-to-end host, database or deployment compatibility. No product FE/BE/SQL artifacts or task files for these reports.

## Explicit package update

The update request authorizes installing AGM for the selected host, not upgrading the host application, installing workflow dependencies, migrating other hosts, publishing this repository or upgrading product bootstrap files.

1. Discover the installed source/scope and exact current path/version. Resolve --to to a verified source ref containing that manifest version; otherwise select the latest installable stable AGM version from the registered source. Never invent a tag, silently use latest for an unavailable pin or select a prerelease implicitly. If already matching, report unchanged. A requested lower version is a downgrade: state it and inspect compatibility before proceeding within the explicit target request.
2. Inspect installed/source customizations and prepare the replacement in a separate temporary checkout if needed, with no changes to the user's working tree. For a source checkout, run its documented generation/validation after reading its instructions. Preserve local modifications through a recoverable copy or scoped merge; if their intended behavior conflicts with the replacement, ask only for that concrete decision. Record recovery source/path and current registry/scope before an operation that replaces or removes a package. Never rewrite installed/generated files by hand or delete a cache tree.
3. Use actual host help and supported native management:
   - Codex: inspect `codex plugin --help`, `codex plugin marketplace --help` and `codex plugin add --help`. Refresh only the selected marketplace using the supported upgrade operation, then install/reinstall the selected AGM entry. If replacement requires remove/add, validate replacement and preserve recovery first. Never invent `codex plugin update` or confuse marketplace refresh with installed package replacement.
   - Claude: inspect `claude plugin update --help` and marketplace help, preserve the installed scope and update the exact `agrimap-agent-skills@agrimap-agent-skills` entry. For a pin, use a verified pinned source/marketplace supported by that CLI; `update` alone selects latest, not --to.
   - Antigravity: inspect `agy plugin --help` and `agy plugin install --help`; use `agy plugin install <verified package source or local directory>` and verify with `agy plugin list`. Do not invent `agy plugin update` or a version flag. Use its supported replacement flow; when uninstall/reinstall is required, prepare the staged package and backup before removing only the selected AGM plugin. Leave legacy Gemini installations untouched.
   For a pin unsupported by the manager, prepare a validated checkout at the proven ref and use a supported local installation source, preserving the prior registration for recovery. If a manager cannot select that source without changing unrelated registrations, stop only that installation with evidence and a concrete alternative. Do not silently change a shared marketplace's source.
4. Check every command result before continuing. On failure, preserve diagnostics and perform the prepared scoped recovery when safe; report recovery success/failure honestly. Avoid automatic retry loops. Read the installed manifest and selected host listing again; require the requested/resolved version and correct path/source before reporting success. Recheck affected readiness only. Tell the user to open a new session; the running session can still hold old instructions. Report before/after version, selected host, source/ref, modified installation and remaining limitations.

Official Antigravity format/commands: [Plugins & Skills](https://antigravity.google/docs/cli/plugins), checked 2026-09-10. [Migration](https://antigravity.google/docs/cli/gcli-migration) retains GEMINI.md and AGENTS.md; do not rename those files. Host CLI availability and actual registration must be verified per installation.
